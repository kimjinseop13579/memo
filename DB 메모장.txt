   테이블 설계

정규화란?
 - 데이터를 잘게나눠 규칙을 정하는 작업
   데이터가 커지면 꼬임,중복,오류가 발생되는데 이를 막기위한방법
   공식정의 -> 데이터 중복과 이상현상을 제거하기 위해 테이블을 
   구조적으로 분해하는 과정

이상현상
1. 삽입 이상
   학과명이 없어 학생을 등록못한다.
   학원에서 새로운 과정을 개설했다. 새 과정을 테이블에 
   저장 해야되는데 아직 수강생이 없어 등록 못한다.

2. 갱신 이상
   같은정보가 여러행에 중복되있어, 일부만 수정하면 데이터가 달라지는 문제   

3. 삭제 이상
   어떤데이터를 지웠더니 원치않는 다른 데이터까지 같이 사라지는 문제

정보화 규칙
1. 한테이블은 하나의 주제
2. 하나의 컬럼에는 하나의 값
3. 기본키로 모든 데이터가 조회가 가능해야함
4. 파생정보는 저장하지않는다. 
   -> 생년월일 저장했는데 나이를 또 저장하는것

정규화 단계
제1정규화(1NF), 제2정규화(2NF), 제3정규화(3NF)
보이스-코드 정규화 (BCNF), 제4정규화(4NF),
제5정규화(5NF), 도메인-키 정규화(DKNF), 제6정규화(6NF) 

제1 정규화
 -> 테이블의 모든 컬럼에는 더이상 쪼갤수없는 원자값이어야한다.
     1정규화를 했을때 외래키가 반드시 필요한것은 아니다 필요한경우가 있지만 모든경우는 아니다.
     하나의 컬럼에 여러개의 값이 들어가지 않아야한다, 같은이름의 컬럼(제목1,제목2,제목3) 을
     사용하는것도 1정규화에 위배된다.

테이블들의 관계형성

테이블 관계란 서로 다른 테이블의 데이터가 어떻게 연결되는 지를 나타내는 구조

테이블 관계가 필요한 이유
정규화 적용 후에 데이터는 나뉘어 있고 화면과 조회에서는 다시 하나로 합쳐서 봐야한다

pk + fk 로연결
JOIN 으로 함께 조회

정규화는 저장을 위해 나누는 작업이고
관계형성은 조회를 위해

관계
1:1(one to one)
한 행이 정확히 한 행과만 연결

회원 <-> 프로필
거의 쓰이지 않음
단, 보안 /확장/ 선택적 정보 분리 목적에 사용

1:N (one to many) OR N:1
하나는 여러개를 가질수있다
외래키는 항상 N쪽에 있다

학생(1) <-> 수강기록(N)
한학생이 여러개의 강의를 수강함
주문상품(N) <-> 주문(1)
하나의 주문으로 여러개의 상품을 주문함

N <-> N (many to many)
서로 여러개를 가진다.
직접 연결 불가 , 중간테이블 필요

학생(N) <-> 강의(N)
학생(N) <-> 등록(1) <-> 강의(N)

한 학생은 여러 강의를 수강할수있다.  한강의에는 여러학생이 수강한다.
학생(N)  <-> 수강(N)

한 회원은 여러 주문을 할수있다, 한 주문은 한 회원에 의해 생성된다.
 회원(1) <-> 주문(N)
 회원의 PRIMARY KEY 로 조회를 했을때 주문은 여러개 나온다
 주문쪽의 키로 회원을 조회하면 한명의 회원만 나온다

 한 주문에는 여러 상품이 포함될수있다
 한 상품은 여러주문에 포함될수있다.
 주문(N) <-> 상품(N)

게시글 하나에 여러장의 이미지 게시 가능하다
하나의 이미지는 하나의 게시글에 사용가능하다.
게시판(1) <->이미지(N)

강의(N)<-> 강사(1)
